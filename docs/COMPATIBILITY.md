# Compatibility and privacy boundaries

This is a local CLI-hook integration candidate, not a certification that every Claude or Codex surface works. No paid inference, subscription credentials, transcript reads, source reads, or authentication changes are used. Practice requires no provider client. An explicit Check version or Choose executable action may launch a native client binary with only `--version`, a two-second deadline and an isolated configuration home; it never starts a task. Clients are never launched automatically.

## Provider surfaces

The app bundles `dist/compatibility.json` inside its ASAR, sourced from `packages/adapters/compatibility.json`. It records adapter/protocol/fixture versions, candidate surfaces, installed hook signals, identity support, known limitations and references. `certifiedClients` is empty: neither version discovery nor a received local hook establishes certification. Add a certified provider/version/platform/surface entry only after the real-client release matrix and trust/permission/interruption checks have recorded evidence.

| Surface | Candidate integration | Current evidence and limits |
| --- | --- | --- |
| Claude Code local CLI | User-scoped `~/.claude/settings.json` command hooks | Synthetic schema/merge/privacy tests only; real signed-in start/permission/stop testing remains a release gate. `Stop` does not cover interruption; arbitrary questions can lack attention signals. |
| Codex local CLI | User-scoped `~/.codex/hooks.json` command hooks | Synthetic schema/merge/privacy tests only; complete provider-native trust review, then validate the installed client version. `Interrupt` is mapped where documented. |
| Claude/Codex desktop, IDE, browser, cloud and remote sessions | Unverified | No blanket compatibility claim; use practice unless the actual local surface demonstrably emits the enrolled hooks. |

Hook groups use UserPromptSubmit, PreToolUse, PermissionRequest, Stop and SessionEnd; Codex additionally uses Interrupt; Claude uses Notification with matcher permission_prompt, Elicitation for attention and StopFailure for terminal failure. Subagent-specific hooks are never installed. Helper payloads with agent_id, parent_session_id, is_subagent, or a non-main agent_type are ignored. Unidentified subagent payloads remain a real-client validation concern. The current Claude candidate includes StopFailure and Elicitation from the official hook contract. This replaces the earlier decision to omit StopFailure; schema acceptance and actual delivery still require version-specific validation before release certification. Older client versions are unsupported unless tested.

Helper adapter 1.2 classifies Claude `PreToolUse` for the exact built-in names `AskUserQuestion` and `ExitPlanMode` as attention, because they ask for an answer or plan approval. Only the tool name is inspected; questions, plans and all tool inputs stay out of transport/storage. The existing hook configuration suffices. A later ordinary tool signal may resume the wait; answering without a subsequent hook leaves the game conservatively hidden. Arbitrary conversational questions, custom/MCP interaction tools, custom `--agent` roots, and older payloads without tool names remain unverified/limited. The helper's root guard still rejects a non-main agent type even without an agent ID. No command output, decision or response is returned to the provider.

Official schema references reviewed October 11, 2026: [Claude hooks](https://code.claude.com/docs/en/hooks), [Codex hooks](https://learn.chatgpt.com/docs/hooks). No client version is certified by merely installing configuration. Managed settings can override user hooks; trust review cannot be bypassed by this application.

## Local transport

The native Go helper has a 240 ms process wait budget and always exits zero without stdout/stderr in hook mode, including malformed input, no host, blocked stdin and IPC failure. The external client timeout is one second. Input is bounded to 256 KiB, normalized frames to 16 KiB, and concurrent broker connections to 16. Only root-session hashed identity, provider, event kind, optional bounded turn ID, random event ID, and adapter version are emitted. Raw cwd is used for hashing inside the helper and never transmitted.

Windows broker pipes use a protected DACL granting access to the current user SID only. Pinned go-winio v0.6.2 sets FILE_PIPE_REJECT_REMOTE_CLIENTS in pipe creation (`pipe.go`). The pipe name must start with `\\.\pipe\country-club-`. Mac uses a Unix socket inside a 0700 directory, chmod 0600 socket, and refuses existing socket paths. The connection file must be a regular file; Unix group/world permissions are rejected. Application-created Windows connection/config files must inherit current-user private ACLs from their containing directory. A minimum 32-character installation token is compared in constant time before any broker event is output.

## Safe setup and removal

Windows Claude hooks use the official `command` plus `args` exec form: the absolute helper executable is launched directly, and each argument is passed literally. Git Bash/PowerShell shell selection is bypassed. The previous quoted command string failed to parse in the documented PowerShell fallback; the retained before-fix probe records exit1 while direct/call-operator controls exit0. New source probes and packaged lifecycle checks use the exact reviewed executable and argument vector. Existing shell-form connections remain unchanged until a fresh review/apply upgrades their owned entries. Client versions without exec-form support remain unsupported until tested; the installed Claude version has not been certified merely because the official current contract documents this field. See [command hook fields](https://code.claude.com/docs/en/hooks#command-hook-fields).

The Windows helper is built with the GUI subsystem to avoid allocating a console. It creates no GUI window and continues using inherited stdin/stdout pipes for broker and hook work. An isolated console-subsystem baseline and actual packaged helper pass metadata, silent passive delivery, private payload exclusion and stdin shutdown checks. Direct, cmd, PowerShell call-operator and available Git Bash invocations are exercised through Unicode paths. PowerShell call-operator acceptance validates that invocation syntax only; it does not certify arbitrary shell-form provider configuration. Edited exec arguments and wrapper arguments that still reference the helper block both app and native uninstall cleanup, preserving configuration, ownership and the helper for manual review.

The wizard previews exact Country Club hook entries, excluding unrelated settings and third-party commands; applying rederives the projection in the main process and rejects changed full-file hashes or forged contents/paths. Complete original configurations remain in private local rollback backups. Existing hook groups and unrelated settings are preserved. Symlink files and parent directories are rejected. Windows paths containing quote, percent, exclamation or shell operators are refused with an actionable error; spaces, Unicode and apostrophes work with quoted paths. Unix paths use POSIX single-quote escaping. Provider JSON must parse; disabled hooks are not automatically re-enabled.

`config-patches.json` stores a provider-keyed ownership ledger: configPath, exact event/group entries, backupPath and installedAt. Backups are private and local. Removal structurally deletes only unchanged owned groups. User-edited groups remain and need manual review. Backups are never restored over concurrent changes. Installation intent is saved before provider mutation, so a failed write can still be cleaned up. Hook changes should be made only while clients are idle; external concurrent writers cannot participate in this app's filesystem transaction.

The installed native helper also accepts `--cleanup --data-dir ABSOLUTE_DIRECTORY` for OS uninstall. It derives provider configuration paths from the logged-in user's home, validates ownership paths, refuses symlink files/ancestors and malformed JSON, and removes only unchanged ledger groups. It never deletes saves or provider authentication. Exit 2 indicates cleanup needs manual attention; backups remain for recovery. macOS removal should run as the intended logged-in user, never as root on behalf of every user.

Modified groups that still reference an owned helper command prevent cleanup: ownership and the edited configuration are retained, so an uninstaller can preserve the working helper instead of leaving dead commands. Restore or manually remove those references and retry. Failed integration upgrades retain ownership for both previous and proposed commands until the provider write succeeds. Malformed, read-only, linked or inaccessible settings/ownership files return limited connection diagnostics during startup; practice remains available without repairing or overwriting those files.

## Release gates

Verify real installed client versions, native trust flow, normal task start/stop, permission, interruption, nested agents, ambiguous ordering, blocked input, crashes, connection loss, and helper absence without changing agent decisions. Validate Windows focus and installer behavior in a clean profile. Mac binaries and PKGs require hosted arm64/x64 CI plus signing/notarization and real logged-in desktop tests. Synthetic tests and cross-compilation do not certify these behaviors.


## Installation-scoped identity

Adapter 1.2 requires a 32-byte identityKey in the local connection file and derives its session pseudonym through truncated HMAC-SHA-256. The private identity-key file persists across restarts independently of the rotating IPC authorization token. Hooks keep their existing command/path; no enrollment patch is needed, but provider-native trust may need review after any binary update. An older helper ignores the new field but emits its older identity scheme, so an upgraded application/helper must be packaged together; the packaging gate checks exact ASAR manifest bytes and queries the bundled native executable for adapter/protocol/schema, identity scheme, OS and architecture. Installed native identity acceptance verifies the actual HMAC behavior. Metadata self-reporting is not a publisher signature or independent proof of the algorithm. First key creation clears an incompatible saved selection; new lifecycle evidence selects or permits selecting a fresh root. Invalid keys disable the broker while retaining practice and original bytes. No provider version is certified by this change.

## Windows npm Codex discovery

An explicit Check version now also looks for the native Codex executable in three bounded Windows npm layouts under existing search directories: a nested platform package, a hoisted platform package, or the older bundled vendor directory. Only the current architecture's fixed paths are considered. Direct native candidates retain priority; an explicit selection is never replaced with another candidate. No wrapper is read/executed, JavaScript module loaded, recursive home search performed, or package installation attempted. Other package managers/layouts may still need manual native executable selection. Automatic client launch remains disabled.

Windows version probes use an extended-length native executable path. A267-character fixture path reproduced spawn ENOENT without this form; the same file succeeded with it. Packaged acceptance includes a guaranteed over260-character case, plus all three npm layouts. The actual IPC action launches only --version, with private configuration homes and no inherited API keys; arbitrary output is discarded and fixture provider bytes remain exact. These checks use a native fixture executable and do not certify hook schema, trust, account status or event delivery.
